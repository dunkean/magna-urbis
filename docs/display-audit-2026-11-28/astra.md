## 2. Why WebGPU is still there

**V — Display.** WebGPU implements a full ground producer and a backend for the dedicated 3D scene. It can prepare pipelines asynchronously, reuse them on the device, and show a preview while the target compiles. V2’s normal tilt, retained cartography, town meshes and glyph rendering already work through WebGL2. Removing only the WebGPU *display* implementation would leave those systems intact, but would make their full-material quality and speed depend on the GL path currently implicated in the white-ground incident. [Map pipeline cache](D:/workspace/self/magna-urbis/web/src/ui/terrain/gpu/device.ts:77) · [Preview selection](D:/workspace/self/magna-urbis/web/src/ui/terrain/gpu/pipelines.ts:44) · [V2 world composition](D:/workspace/self/magna-urbis/web/src/v2/display/composedView.ts:27)

**V-record — There is a measured reason to retain the option.** On November 12, an RTX 4090 run with ANGLE D3D11 and automatic WebGPU ground logged **47.5 s** for first satellite. A forced-WebGL run on that adapter logged **150.0 s**. A later integrated WebGPU build reported **32.1 → 3.8 s** for first satellite and **26.9 → 3.6 s** for first dedicated 3D satellite, including idle prewarm. The latter comparison measures improvements within the WebGPU implementation. The fast archived Vulkan study used WebGL2, a different fixture and an RTX **5090**. These records establish neither a universal backend winner nor a current V2 navigation-FPS advantage for WebGPU. [4090 automatic](D:/workspace/self/magna-urbis/web/out/renderer-load-2026-11-12/diag-auto.log:4) · [4090 forced GL](D:/workspace/self/magna-urbis/web/out/renderer-load-2026-11-12/diag-webgl.log:5) · [Integrated timings](D:/workspace/self/magna-urbis/web/out/renderer-load-final-2026-11-12/REPORT.md:24) · [Vulkan fixture and adapter](D:/workspace/self/magna-urbis/web/out/renderer-load-codex-2026-11-12/REPORT.md:11)

**V — Generation has a harder dependency.** Browser neural inference requires WebGPU, and the model download flow checks that it can obtain a device. Explicit GPU procedural/erosion modes also use WebGPU. Automatic procedural generation has a CPU fallback. Desktop native generation and neural inference are separate services. A global “disable WebGPU” change would therefore remove a browser generation capability without simplifying V2’s WebGL2 presenter. ### The 1,307-second incident

**V — Two ground producers run in sequence in City Bench.** On a changed look, the bench waits for forest/contour inputs, assigns `backgroundKey`, calls `renderRustTerrain`, constructs an SVG snapshot, clears the SVG background, and only then calls `groundRenderer.setLook`, `setRetainedWater` and `setView`. For satellite with hypsometry, `renderRustTerrain` calls `renderMaterialRaster`, combines its result with a neutral raster, and can register further per-region canopy raster work. Despite its name, this route enters TypeScript and an offscreen or page **WebGL2** context. The enhanced fragment keeps material choices behind runtime uniforms. Its cache distinguishes base/enhanced programs, and its compile-status check, link-status check and `readPixels` are synchronous. V2’s normal GPU branch sets the ground look and returns without this snapshot step. [Bench ordering](D:/workspace/self/magna-urbis/web/src/ui/citybench.ts:519) · [Satellite raster and canopy](D:/workspace/self/magna-urbis/rust/bridge/terrainRender.ts:247) · [GL context](D:/workspace/self/magna-urbis/rust/bridge/terrainMaterialContext.ts:14) · [Shader and link](D:/workspace/self/magna-urbis/rust/bridge/terrainMaterialRaster.ts:179) · [V2 early return](D:/workspace/self/magna-urbis/web/src/v2/display/groundProducts.ts:218)

**I — Most informative diagnosis.** The D3D11 run can encounter both the legacy GL material compiler through ANGLE/D3D11 and the visible map compiler through Dawn/D3D12. A busy GPU-process CPU thread and an idle renderer process fit either a compiler wait or a synchronous operation waiting behind it. Switching to ANGLE/Vulkan changes the GL translator/driver route **and**, in the reported headless configuration, makes WebGPU adapter acquisition return null. That changes two variables at once. Time the hidden material compile, link, first draw and readback separately from creation and first draw of the visible map/aux pipelines. A timestamp immediately before and after `renderRustTerrain` would tell the owner which side of that boundary consumed the 22 minutes. ## 4. White ground, false readiness and parity defects

**V — City Bench can announce success before a correct frame exists.** `groundApplied` is assigned after the draw requests, without awaiting a completed frame. GL’s `data-map-variant-ready` means the main and auxiliary programs linked. It is written before the ground draw and does not assert correct framebuffer contents, water, town or presentation. WebGPU submits work through a different route. Its `variantReady()` can even log that a pipeline failed and return with a stand-in.

# Existing Magna sources and regional exchange

`magna.ts` reads existing `TerrainData`, city `World`, `Building3dScene`, and retained `.decor` files. It never generates replacement cities. `exportMagnaBuildings` calls the same native triangle iterator used by the current renderer and picking, preserves source IDs/material slots/footprint holes/absolute altitude, and labels cartographic projections `cartographic-proxy`, `nativeRealization: false`. Footprint rings remain in source map XY; triangle positions use the metric convention below. The winding reverses after the axis permutation so outward normals remain correct.

Map `(x,y,height)` maps to physical `(X,Y,Z)=(x,height,y)`, in metres. Source raster samples are cell centres: `(x+(i+0.5)*width/n,y+(j+0.5)*width/n)`. A renderer may subtract a render origin but must retain these canonical coordinates for material phase and identity. The local Godot consumer uses this convention; browser renderers can adapt it independently.

`createLiveInfiniteTerrainProvider(settings, sourceForReply)` runs the existing `sampleRustTerrain` bridge in a dedicated worker for each surface request. Aborting terminates that worker; its generation queue never blocks the active page terrain queue. Source metadata is explicit: changing display sampling resolution does not prove a new source LOD. `createInfiniteTerrainProvider` exposes the same contract with an injectable bridge for runtime transport and testing. Existing Infinite Generation sampling accepts square regions, 64–1024 samples per side. Clamping can change requested spacing; consumers must use the returned `grid.spacingM`. Source LOD is an opaque provider number: only `nativeSpacingM` is comparable between providers.

`infiniteRefinement.ts` is the actual retained-source HTTP provider. `createInfiniteRefinementProvider(server,field,options)` registers the existing retained B-spline control grid at `/refinement/register`, then calls `/refinement/tile` for each physical request. Unlike the display-specific `TerrainRefinementSession`, it retains the returned raw samples as physical terrain and does not replace them with spline coefficients. Metadata `sourceCell`, `lod`, `version`, `decoderUsed` comes from the real response. Requests propagate AbortSignal, retry an expired registration once, and honor the service's minimum spacing. Existing neural `/generate` returns a fixed 1024² FP32 field; the separate refinement endpoints provide the incremental path.

`stream.ts` is the transport-neutral runtime bridge. Requests carry `{id,worldId,bounds:{minX,minZ,maxX,maxZ},resolutionM,sourceLOD?}`. `createSurfaceStreamHandler` calls the provider and a supplied compiler, then checks cancellation/world identity before returning `{id,worldId,sourceLOD,payload}`. A file bridge writes requests to `requests/<id>.json` and publishes the compiled packet atomically in `responses/<id>.json`; only complete responses should replace a viewer world. The provider must report actual generator resolution/LOD, not echo the request hint. Source changes must use a new worldId.

`neuralEarth.ts` defines a versioned, metric, georeferenced regional package independently of Godot. The caller supplies the real longitude/latitude/altitude origin, +Z azimuth, CRS and vertical datum; local Magna maps do not imply a geographic position. +X azimuth is +Z minus 90 degrees; the east/up/south Magna frame therefore uses +Z azimuth 180 degrees. Layer origins are first sample centres. Explicit east/north rotation helpers are available; planetary projection remains the Neural Earth consumer's responsibility. Layer dictionary keys, IDs, source keys, source LOD/native spacing, seasonal dates and elevation-correction status survive typed-array serialization. Float NaN and infinities use explicit markers; invalid integer ranges, coercions and metadata are rejected. Opaque feature keys are never interpreted as typed-array tags. Unit conversion is explicit; already elevation-corrected climate must not receive another lapse correction. Version mismatch is rejected.

Offline `.decor` captures preserve their generator query and actual retained settlement raster, hydrology IDs and source geometry. That raster can have been sampled from displayed B-spline coefficients; it is preserved exactly for city compatibility. Captures are not evidence of fresh Infinite Generation refinement. Their original source LOD was not recorded: `sourceLODKnown:false` marks `sourceLOD:0` as a schema placeholder, not an observed level. Refinement responses explicitly mark known LOD. `climate.ts` exactly follows bench rules: named presets ignore numeric overrides; `climate=custom` accepts finite values and falls back on missing/malformed values. It converts thermal standard deviation from centidegrees and approximates seasonal peak amplitude as sqrt(2) times that standard deviation. World inputs and runtime packets default to Magna's 18 degrees C and 1000 mm/year, with explicit source climate accepted. It retains the sea-level temperature convention, with a single subsequent terrain lapse correction. Dry source cells carry NaN water levels.

Export a real retained terrain with `npx tsx scripts/export_surface_world.ts INPUT.decor OUTPUT.json`. For a small reviewable source crop, append `--crop '256,256,64'` (raster column,row,size). Crop samples keep their physical world origin and native spacing. The source geography and generator metadata remain in the packet. No synthetic scene is substituted when source data is unavailable. Cold building exports require the retained complete chunk scene; unresolved cold references are rejected.

Both packet helpers include stable population candidates in an explicit `candidateBounds` window. The default is a bounded 320 m square at the territory centre, clipped to the available terrain; callers can request another physical window with `candidateBounds`. This is a bounded export selection, not a change to population identity. `exportSurfacePacket` also maps existing road segments to `urban.roads` with physical widths, source segment indices, original class/surface and world-space points. Runtime callers retain city data in `source` or provide the same road mapping themselves.

Use `candidateBounds:'all'` or CLI `--candidates all` for the complete retained territory. Candidate limits are explicit through `candidateLimit` / `--candidate-limit`. `encoding:'binary'` returns the raw typed-array world for the binary packager, without an intermediate giant JSON string. The CLI accepts a separate `--native-scene FILE.json`; its unchanged source coordinates and unasserted terrain lineage are clearly labelled as an external diagnostic.

Export offsets have separate meanings: `originX/originZ` translate the common physical frame (terrain, visual building triangles, accepted occupation, footprints and roads together). `terrainOriginX/terrainOriginZ` describe a cropped raster's source corner within unchanged source city coordinates. The CLI uses the latter. Source metadata stays in its original frame, with `sourceToWorldTranslation` recorded. Urban roads use metric XZ pairs; source footprint structures retain XY-shaped point objects carrying metric XZ coordinates after translation.

Accepted occupation and visible overlays remain distinct: `urban.occupationBuildings` retains accepted IDs, child occupation surfaces and physical ground constraints, while `urban.buildings` holds visible triangles. Explicit empty accepted occupation stays empty. `occupationFromMagnaScene(terrain,scene,roads,base)` rasterizes the existing accepted source surfaces and physical road widths at the canonical terrain sample centres. `occupationFromMagnaWorld` reads existing 2D city masses/streets without creating native records; `worldToSurfaceInput` includes it automatically. `occupationFromMagnaSurfaces` accepts direct physical surfaces. Boundary-touching cells are conservatively excluded so thin walls and roads cannot disappear between samples; courtyard interiors remain free at the available raster resolution. This is an exclusion mask, not a claim that coarse DEM spacing resolves architecture. Packet helpers apply these exclusions before population selection; runtime callers can supply roads through options.

The refinement provider exposes a detached `registration` snapshot. Its source identity includes the actual retained registration ID as well as the seed; a newly registered source cannot silently reuse the same lineage after source expiry or terrain edits. Consumers must recompile canonical context for a new registration identity before retargeting refinements.

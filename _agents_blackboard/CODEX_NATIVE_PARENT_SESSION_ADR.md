# Native parent session v1: retained exact occupation

Status: contract proposal, no implementation/build/product change yet. Stateless parent batch V1 stays immutable and is a primitive only when supplied a complete context. Automatic city generation will use this retained native session. Core is untouched.

## Public protocol (UI/performance agreement, details below)

Capability `houses.native-parent-session-1` in the existing local/Wasm lists, in addition to parent-batch/pair/Std capabilities. New scoped-Std local routes `/houses/begin-parent-session`, `/houses/plan-parent-session`, `/houses/ack-parent-session`, `/houses/abort-parent-session`, `/houses/release-parent-session`; WASM names `begin_parent_session_json`, `plan_parent_session_json`, `ack_parent_session_json`, `abort_parent_session_json`, `release_parent_session_json`. No implicit resume after reload. Legacy routes and stateless parent APIs remain unchanged.

Begin input `{schema_version:"native-parent-session-1",run_id,source:{fingerprint,revision,coordinate_space:"world-metres"},total_requests,settings}`. `run_id` is a fresh administrative nonce, unrelated to architecture seeds. Source/settings and canonical input partition identity freeze for this run. `revision` is the opaque exact digest of the actual terrain/layout/partition revisions, not an invented cross-engine certificate. The session id includes a fresh engine-incarnation nonce AND run_id; URL/revision/counter alone is insufficient after restart. Begin returns `{session_id,source,generator_version,partition,offset:0,total_requests,limits}`. Settings are NOT resent or taken from live controls on each page.

Plan input `{schema_version,session_id,source_fingerprint,revision,expected_offset,key,requests,footprints}`. At most64 requests; all original request fields/neighbors are preserved. No prior-city geometry is sent. Empty plan batches are rejected; EOF uses offset==total and release. For total_requests=0, begin returns complete metadata (batch schema/generator/zero counts) sufficient for a durable administrative empty scene, then release; it never invents a parent/archive. Native request digest is over the exact typed data using lossless f64 encoding; whitespace/numeric spelling is not geometry authority. Same key with different typed content or offset/revision fails before calculation.

Plan reply `{ok:true,data:{receipt,batch_json,context_report}}`. `batch_json` is the sole opaque native batch JSON string; the client checks its exact UTF-8 SHA before parsing it. No duplicate parsed batch object is sent. Receipt `{session_id,source_fingerprint,revision,key,offset,completed,total,request_sha256,batch_sha256}` binds the actual native output. `batch_json` encodes the native ParentPlanBatch already agreed. Its hash is computed from the actual native serialized batch bytes, not a JS reserialization. Exact pending reply bytes are retained for retry with no redraw/recalculation. An identical request arriving while calculation is active returns explicit inflight, never starts a second calculation. No next batch before ACK. Output-budget failure aborts this run; it never silently repartitions/replans.

ACK input repeats the complete receipt. Frontend writes ALL fragments/derived indexes of that logical batch durably first, then sends ACK to native, and only then reads/plans the next prefix. ACK validates the exact pending identities/hashes/completed, inserts its true 2D leaves once, discards pending transport, and returns committed offset. Repeating the same already accepted receipt is idempotent without duplicate insertion. Mismatched/stale/future ACK fails. A bounded last256 acknowledgement-receipt window makes this explicit; no graph is kept in it. An older receipt outside that window returns stable ack_history_expired and NEVER reinserts or advances anything. Plan retry after ACK returns already_acked, not an invented old batch; only the current pending exact reply bytes are retained.

Abort/release input `{schema_version,session_id,source_fingerprint,revision}`. Ready/pending sessions release immediately. Abort during local calculation marks closing; calculation drains outside locks, suppresses pending publication/ACK, then removes the run. Wasm is synchronous: cancellation is observed on return; this does NOT pretend to interrupt an executing native call. UI drains pending calls and releases/aborts in finally, including stale epoch/error paths. If stage creation fails after native begin, cleanup still runs; a stage-cleanup failure must not prevent native cleanup, and errors are aggregated. Registry caps and idle cleanup are administrative failures, never geometry impossibility.

## Exact index and the actual solve paths

Each run retains ONLY exact immutable 2D occupation leaves: complete member bodies/courts/native features, parent paths/passages/shared context, and separate roof footprints. No prior PlanBuilding, native parent graph, resolved source, archive, terrain raster or catalogue result is retained. Leaf owner is a typed prior-prefix ordinal, separate from current-batch request IDs; no string prefix exclusion. A broad-phase native grid/overflow index returns exact leaves for the bounds of each REAL candidate surface; narrow-phase geometry retains existing physical thresholds. Collision area is against the UNION of relevant leaves, not per-leaf testing or summed areas (which mishandle cumulative small contacts or duplicate overlap). No presumed cadastral query envelope, invented padding, clipping, hull, tolerance change or roof-as-land conversion.

The synchronous admission scope borrows an immutable shared index handle for the call, without cloning the prefix. Common visual and minimum admissions check actual complete land versus prefix land AND roofs, and actual roof versus prefix land; roof/roof alone remains allowed. Real proposed passages/straight/analytic/one-bend paths query the same index BEFORE selecting that connection, so ordinary alternatives continue. Existing necessary candidate rectangles/roof envelopes query exact prefix occupation at their actual generated poses; these guards are necessary checks, not new solves. Guides that only use a domain to choose dimensions are not asserted complete/optimal. The final guard is defensive, not a replacement for these actual candidate/connector hooks.

Phase1 still finalizes all old results including growth/need continuation, reserving current results only after final selection. Phase2 reserves ALL other current finalized parents including later Singles, plus the native prefix index; it queries the same index for necessary bodies/roofs, connectors and final members. One bounded existing pair attempt per covered request. Failure keeps the entire still-valid legacy result. No new source draw/resolution/trial, no reduced target/population, no household credit. Archive/outcome/realize authority is unchanged from parent batch.

## Registry and bounded publication

Registry lookup/lease/commit holds a short registry lock; it never holds that lock while planning, unions, serialization, realization or cleanup of large geometry runs. One in-flight lease per run, independent runs isolated. The index is moved/shared immutably into that lease, never copied per batch. ACK mutates the run index only after the lease has ended. Pending is at most one batch/64 parents and64MiB output, plus its exact 2D leaves; after serialization it may discard native graphs entirely and retain cached reply bytes. Explicit administrative caps cover runs, total input requests/batches, 2D vertices/index references/retained bytes, pending reply and ACK log. No truncation; no heap/time bound claimed from JSON limits. Proposed caps: at most4 runs; one pending <=64 parents/64MiB reply per run; <=1,000,000 total requests; <=32,000,000 retained 2D vertices, <=8,000,000 grid references and<=512MiB explicitly accounted retained leaf-coordinate/identifier bytes across the registry; <=4096 hit parts and262144 hit vertices per exact query, with a complete administrative error instead of truncation. All caps are independent and not promised simultaneously attainable. Last256 ACK receipts are <=1MiB metadata per run. Native monotonic clock / WASM performance clock provide15-minute idle cleanup on subsequent API calls; a busy expired run is marked closing and drains, never silently reconnected. Pending output bytes and leaf/index accounting are separate from heap/allocator peaks. Exact constants and count formulas are frozen with code, not inferred from serialized JSON. The client fixes request partitions against the known input/Std budgets only; preceding native geometry is absent from wire.

Root proof required: same-key retry/changed content/inflight; durable ACK ordering and failed store rollback; ACK idempotency; abort/compute drain and cross-run isolation; no global lock held while a blocked run computes; actual group page1 -> exact prefix lookup -> page2 body/path/features/roof guards, including an actor just outside nominal parcel bounds; two roof directions plus land/land and roof/roof control; current later incumbent reservation; source/settings/revision rejection; full output archive/realize; no old API state leak. UI uses this session on the actual CityBench worker AND fallback, not a second demonstration.

## Implementation boundary agreed before code

Five session routes must bypass the legacy response Value path as well as the legacy input decoder: raw Std input -> typed generation -> bounded native serialized receipt+batch -> exact cached reply bytes. Local and Wasm call this same raw native boundary. No Value reparse/reserialization at a retry, no JSON.stringify verification claim. Wrappers may make bounded transport copies; they are not included in the retained index-byte estimate.

Index query hooks cover actual land/land as well as both roof directions, including tolerated candidate projections just outside the nominal parcel and complete paths/features. Broad-phase source/parcel queries may help the old constructive guide but NEVER establish full coverage. Ordinary connection alternatives consult the exact candidate-path query before selecting a result. No root/Core or source catalogue change.

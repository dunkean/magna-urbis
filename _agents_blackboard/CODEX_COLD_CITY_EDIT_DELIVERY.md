# Édition atomique d’un bâtiment froid — 23 octobre 2026

Livré : `web/src/ui/urbanColdCityEdit.ts` et 12 tests CPU. Extension étroite de `urbanBuildingChunkStore.ts` : `iterateUrbanBuildingChunkRecords()` fournit `{descriptor, stored, delta}` authentifiés ; l’itérateur existant délègue sans second décodage dans cette couche. `appendStored` garde sa validation d’écriture habituelle.

`editColdCityBuilding({backend, session, original, edited, settings?, sourceFingerprint, cancelled?, signal?, generate?, limits?, maxChunkBytes?})` retourne `{applied:true,state:ColdCityState,replacement:NativeBuildingProjectionScene}` ou `{applied:false,message}`. `replacement` projette seulement le vrai bâtiment remplacé via `projectNativeBuildingRecords`, alimenté avec la table native complète ; sa sortie conserve les couleurs utiles selon le contrat du projecteur, sans parent natif, archives, volumes, niveaux ou meshes. Projection préparée avant commit pour valider avant publication durable. Le générateur par défaut appelle `planUrbanBuildings` avec `executionRuntime` courant ; injection possible. Aucun placement n’est produit en JavaScript. L’identité bâtiment/parcelle reste constante ; conversion espace libre et offset non nul refusés explicitement.

Le voisinage est lu via la session, avec l’AABB exacte de `architectureEdits` : cadastre, domaine constructible, toit et extrémités des accès élargies de leur demi-largeur. Une lecture tronquée refuse l’édition avant génération/staging. Le sous-ensemble natif explicite contient uniquement de vrais enregistrements sélectionnés/voisins et leurs archives/matériaux ; les DTO visuels ne sont jamais envoyés au natif. `editArchitectureScene` réutilise l’occupation physique cumulative et supprime seulement l’ancienne occupation du bâtiment sélectionné. La version de la réponse doit égaler celle de la ville entière, même sans voisin dans le sous-ensemble local.

Après admission, copie séquentielle vers une nouvelle génération : tous les chunks étrangers passent par `appendStored` sans réencodage/recompression ; seul le chunk cible est réencodé, à ordre constant, avec le bâtiment sélectionné remplacé et les archives nécessaires (chaînes conservées exactement). La table native de matériaux est conservée, y compris les IDs absents des volumes simplifiés ; toute redéfinition partagée ou collision d’archive est refusée. Comptes identiques, remplacement 1→1. La ville et la projection précédentes restent intactes.

Le manifeste cible est vérifié contre le descripteur de la session. Le pointeur global actif est capturé avant toute lecture/génération uniquement pour le CAS final : une autre ville active n’invalide pas une ville historique authentifiée. Un changement concurrent du pointeur fait échouer le commit. Annulation vérifiée entre les étapes et juste avant la transaction ; `AbortSignal` peut interrompre une transaction active. Après commit durable, l’opération rapporte le succès : une annulation ultérieure ne peut pas annuler ce commit. Refus, erreur native, corruption, quota ou échec de commit nettoient le staging et préservent l’ancien état.

Budgets par défaut : 256 tuiles, 2 048 candidats, 512 bâtiments, 16 chunks / 16 Mio encodés pour le voisinage ; traversée de copie limitée à un chunk de 64 Mio maximum. Ce sont des budgets d’octets encodés, pas une mesure ni une borne exacte de heap JS. La copie est O(nombre de chunks) en IO et stockage pour chaque nouvelle génération ; aucune déduplication physique entre générations n’est promise. Les anciennes générations restent retenues.

Validation : **41 tests verts / 5 fichiers**, dont les 12 nouveaux sur six vrais bâtiments C en trois petits chunks : conservation exacte des chunks/payloads/signaux zéro négatif, archives et matériaux sélectionnés, occupation voisine, troncature, incohérence de version/source/site, offset, refus/exception/quota/commit, annulation active et CAS concurrent. Test du générateur injecté : aucune admission native réelle revendiquée. Aucun navigateur, serveur ou Cargo utilisé ; IndexedDB navigateur réel et UI non validés ici.

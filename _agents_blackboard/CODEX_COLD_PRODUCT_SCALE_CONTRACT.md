# Product performance: cold city100k→million contract proposal

Read-only product audit + isolated root-only measurement driver. No product code change is proposed/applied by this document. The separate authorized vendor LF correction is documented in `CODEX_POLYGON_VENDOR_LF_FIX.md`. The early affine prototype remains isolated; root reports16scoped V3 tests passed and a45.9ms single sample, which is still not a CPU performance solution for cities.

## Observed current product paths

1. `terrainUrban.ts` generate cold branch calls `sceneClient.runCold` without `retainSites:false`. `urbanScene.ts::receiveCold` appends every `UrbanSiteVisual`; completion builds `createNativeSiteStore`, whose array and byId map retain all site geometry/metadata. This supports real origin constraints for edits, landmark previews and comparisons. Simply turning it off would regress those features.
2. `createColdProjectionAccumulator` explicitly retains complete cartography. `publishColdArchitectureBatch` also feeds every accepted visual to `UrbanBuildingLodRenderer.appendScene`: scene array, records/bounds, identities, byId, sectors, overflow and geometrically growing Uint32 seen remain O(N). DTO surfaces are shared references between accumulator/renderer, not a second complete coordinate copy; indexing nevertheless adds real global structures. Bounded geometry/raster/history caches do not bound this base.
3. `openColdCitySession` without a supplied projection iterates/authenticates/decodes EVERY native chunk to reproject all cartography before restore completes. The existing test explicitly expects all three sample chunks read. Native plans are not retained globally, but restart IO/CPU is proportional to total archive bytes.
4. `createNativeSiteStore` bounds native request cache16entries/8MiB and2inflight; session native read cache is2chunks/8MiB with serial IO. Building id/spatial indexes are ALREADY on IndexedDB; no global JS copy of that durable index is required. `readVisible` has real tile/candidate/building/chunk/byte budgets. Its truncated result is an edit refusal, not a license to display an incomplete city as complete.
5. `readUrbanDisplayBuffers` and Rust `urban::display_buffers_refs` project whole selected layouts/partitions into one binary buffer; request has keys/ids, no viewport/tile/LOD. This is parcel/road data, not cold building cartography. No runtime UI call to `readUrbanDisplayBuffers` was found. `cityCanvas::buildCityScene` still builds full parcel/block/street arrays+bins and parcelById; native source binding retains the authoritative UI arrays. `coldCityFingerprint` serializes each full layout/partition to JSON+UTF8, a transient O(city graph) allocation. Binary display alone is not a tiled-million-city solution.
6. 3D `city3d::syncBuildings` builds a global byId map and `city3dProjectionScene` maps all visuals; `forestOccupation::withBuildingOccupation` flattens all occupation contours, and `UrbanBuildingGround` indexes all ground constraints. A bounded2D window must not make forests grow through offscreen houses or change physical/native foundations.
7. A single cold edit currently traverses/authenticates/parses all stored chunks to check shared material/archive semantics and create its new generation; unchanged payload bytes remain exact, but edit IO/CPU is still O(total city archive). Copy-on-write immutable chunk references plus authenticated global material metadata are a future separate optimization; do not remove these checks merely to make an edit look cheap.

Current LOD tests show local query work independent of1k/10k/100k only AFTER constructing the entire resident scene. The existing Canvas benchmark allocates all100k visuals and requires a browser; neither is a million-house residency/restore proof. Browser surfaces are unavailable in this session; there is no workaround or browser-FPS claim.

## Contract before product implementation

**Identity and durable derivative.** Native archive generation/manifest stays authoritative and export/import remains exact. New optional versioned visual cache is keyed by native scene fingerprint+projection version; each visual payload/index/overview tile has a content hash and known parent chunk/record provenance. It contains only projected child geometry/metadata, never native archives/levels/parameters. Commit a derived-cache manifest only after its parent generation/counts validate. Cancellation/quota/error cannot corrupt or replace the last valid native generation. Stale/missing cache is explicitly pending, not inferred empty; old stores/imports stay readable and can rebuild the derivative one native chunk at a time in the background.

**Near visual tiles and budgets.** Store exact projected f64 child contours/attributes by building ID with durable spatial tile keys; overlapping-tile references must not duplicate native records or miss cross-boundary roofs/occupation. Load only the viewport+halo into a bounded tile/decoded-vertex/encoded-byte LRU with one active IO and latest pending camera. Selected/detail base may be pinned, included in the budget. Declared encoded-byte caps are NOT heap caps: measure decoded graph/ArrayBuffer/peak heap as well. Do not silently cap512buildings and claim a complete view. Evicted geometry leaves all global JS id/record/sector maps; durable indexes remain on disk.

**Complete overview and zoom.** Persist a coarse raster/LOD pyramid generated from the real child footprints/materials/holes during streaming or derivative build. It covers the whole city; selecting a coarser level fits screen tile demand within raster budget, instead of truncating houses. Existing raster budgets are a starting point, not a million proof. Zoom transitions retain valid coarse coverage while exact near tiles load; loading/error is explicit. Appearance/version participates in overview cache identity; no guessed roof/house geometry or native inference is introduced. Far imagery may be display resolution, never an admission certificate.

**Picking and details.** Overview click resolves through the durable spatial index and exact local projected contours/order, including holes/cross-tile buildings; a capped query reports pending/needs refinement, not false “no house” or a random ID. Picking a known ID loads that exact native record/context through the current authenticated bounded reader. Detail meshes remain small window/selection LRUs with cancellation and exact base identity; an evicted/reloaded visual cannot inherit a stale detail by ID alone. Whole-city counters come from validated manifests/aggregates, never resident-window length.

**Original sites and editing.** Persist a lightweight id→original SITE OFFSET index while the ordered worker `sites` chunk is present, plus source fingerprint and a runtime-bound original query descriptor. Never infer offset from accepted building recordIndex: refusals/open spaces make those sequences differ. This enables a site-store interface backed by durable lookup+one true original constraint read, with the current bounded native request cache; no complete site surfaces array is required. Programme target/landmark/comparison views read projected metadata or spatial pages. Restored native handles are ephemeral: editing rebinds only to an exact matching source fingerprint; missing old origin indexes are explicit pending derivative work, not fabricated constraints. Readable plans/details/export remain available. `retainSites:false` becomes safe ONLY after these consumers migrate, not as an isolated switch. An admitted edit keeps native CAS/rollback/material/neighbor guards, then invalidates/rebuilds only affected derivative tiles/overview ancestors; unaffected archive bytes remain exact. Existing O(total archive) copy/check work remains a measured limitation until its own safe copy-on-write tranche.

**3D, forest and terrain.** 3D consumes the same resident window/coarse overview, not the full city array. Terrain/forest exclusion and ground scalar fields become source-owned projected tiles/aggregates covering required terrain samples; replacing a global array with a camera-only subset is incorrect. Native physical foundation height is never changed by the display derivative. This consumer migration is part of the million goal, not optional cleanup after declaring success.

## Small promotable increments and acceptance measurements

A. First persist/authenticate derived visual+origin indexes at chunk write and read them on restore, retaining current complete-visual UI temporarily. This cuts native archive rereads and prepares real lazy site editing; it DOES NOT bound global visual heap and must be labeled that way. Regress exact import/export, stale hashes, cancellation, quota, old-store rebuild, site offsets with refusals and one selected native read. Measure native bytes parsed on valid-cache restore (=0), derivative bytes, first coverage time and restored geometry/metrics parity.

B. Introduce the bounded viewport visual source + complete coarse overview in2D, replacing accumulator/global renderer index/site arrays on this new store version. Regress every above contract (zoom/pan/whole overview/picking/edit/restore); expose resident tiles/vertices/bytes/inflight/queue and coverage status. Keep old mode supported while its limits remain explicit. C. Migrate parcel source display and3D/forest/ground consumers to tiles; separately optimize native generation/immutable edit IO. Completion at million requires these real consumers, not just B's small cache.

Measure100k then1m in fresh processes with fixed viewport and repeated pan/zoom/restore/one-site/detail/edit workloads. Capture actual CPU time, wall p50/p95, OS RSS high-water, post-GC and sampled peak JS heap, typed-array bytes, exact stored/transport bytes separately, native chunk bytes parsed, overview coverage, and counts of resident objects. No fixed hardware-independent FPS assertion. At a fixed window, resident exact geometry/index must plateau while city count increases10×; coarse overview must still cover the entire city, and no correctness budget may be hidden by dropping records.

## Ready isolated headless baseline driver

`web/out/cold-product-residency-audit-v1/probe.ts` calls frozen REAL production accumulator/renderer/site-store functions over replicated actual C child geometry.17hashed inputs (14runtime TS+2fixtures+driver). It reports CPU/phase time, forced-GC residency after global visuals and after sites/byId, sampled heap high-water and OS resource usage, warm viewport-query latency, and exact encoded visual JSON bytes clearly distinct from native wire/heap/FPS. No browser/native/server/IndexedDB run or million admission claim. It writes a visuals checkpoint before allocating all sites, so an oversized/OOM run can remain a failed measured outcome. It has not been executed by this agent. Commands/limits in its README; root runs the1000shape check, then100k and1m as resources allow. This establishes the current global-residency baseline before any product optimization is claimed.

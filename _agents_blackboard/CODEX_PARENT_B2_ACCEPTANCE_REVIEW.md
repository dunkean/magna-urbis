## Écart concret du runner actuel et gate minimal

`city_visual_bench.mjs` attend `probe.final` legacy à la ligne 664. Son probe aux lignes 325–349 additionne `batch.delta/scene.buildings` sans liaison au request ID/source courant ; la ligne 702 qualifie la preuve native par un `/houses/plans` réussi après clic. Il ne comprend pas `parentComplete`/receipts. **Il ne certifie donc pas B2** : timeout probable sur le nouveau seul protocole ; des événements/reçus legacy mélangés ne doivent jamais permettre un faux succès. `parentFingerprint` B4 est une empreinte source, pas un compte parent. Le modal expérimental n’est pas une ville appliquée.

Gate de lecture à brancher après gel B2, sans nouvel outil : l’entrée et l’état appliqué déclarent le mode parent ; absence/incompatibilité du marqueur attendu = incomplet, jamais repli legacy. Observer seulement des scalaires issus du receiver/store : format, scène/fingerprint/source, revision, génération UI, état staging/committed, compte de frontières/fragments et couverture validée, totaux typés, fin native released et commit CAS. Comparer ces identités à la source de viewport et les garder stables avant/après capture. Les reçus complets restent au manifeste ; aucun token natif sensible ni archive dans le rapport. Ne pas substituer `/houses/plans` ou le succès HTTP d’une page au commit parent. Une exécution fallback/WASM valide peut n’avoir aucun HTTP Houses. Parameters_ui confirme ce marqueur appliqué distinct, les identités native/générateur/partition et les picks typés none/pending/member/context-parent ; **ils sont prévus, pas encore écrits ni gelés dans le rendu**.

Cas purs à préparer avec le contrat scalaire B2 gelé : (1) parent attendu + seul reçu Single => incomplet ; (2) chunks manquants, offset/révision/source divergents ou staging => incomplet ; (3) bon commit mais viewport ancien/pending => incomplet ; (4) bon commit et fenêtre exacte locale => local complet, pas overview global ; (5) bon fallback sans HTTP => accepté ; (6) import Single explicitement legacy conserve son parcours ; (7) comptes parents/membres incohérents => rejet ; (8) génération changeant pendant capture => rejet. Aucun test de sélecteur inventé avant ce contrat, aucun test exécuté ici.

Invariants réutilisables dans les 52 captures : mêmes ID, URL brutes, options et caméras ; ajout de preuves de scope/source/commit seulement, sans requalifier les anciennes images. Les gestes UI restent non exécutés : navigateur indisponible et serveur non autorisé, aucun retry ni contournement. Le défaut de lifecycle Worker dispose/cleanup déjà confié à l’UI n’est pas redéveloppé dans cette revue.

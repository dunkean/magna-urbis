## What the contract actually proves

- `houses/src/native_candidate.rs::try_plan` gates automatic inspired domestic/mixed requests, default controls including wealth 0.5, no imposed/exact footprint, and enabled fitting. `compatible` checks current culture/tradition/era/typology, actual principal floors, composition and actual footprint within 10% of target. `checked_plan` checks real bodies/levels, roof rights, supports, terrain/water, neighbours/reserves and native portal/access connectivity. An eligible supplied contract refuses without hidden fallback.
- `admission_witness.rs::build_witness` calls `admission.rs::minimum_native_skeleton`: source minima, canonical seed, and a default `HouseConfig`. This is **not** a draw reconstructed using request wealth. `engine.rs::amount`, `quantity` and parameter drawing show that wealth changes dimensions, floors/body/component counts, roof and other draws. Copying request wealth onto the packed minimum would misrepresent retained architecture. A sized witness needs its own request-sensitive identity/construction; the style-only minimum cache is unsuitable.
- `core/.../building_sites.rs` emits at most 12 recipe IDs from `feasibility::lot_fit`; that tests nominal margined witness envelopes through `parcel_envelope`. Metadata has no variant, hash, pose, actual wealth or target-sized body proof. A fitting minimum does not establish that the requested programme fits. Recipes omitted by this truncated list are not proved impossible. Houses currently has no typed `feasibility` field (`placement.rs::PlacementRequest`), so this metadata is ignored there.

## Smallest safe next experiment

Add a bounded optional metadata DTO, then an **after-refusal** recovery beside `plans.rs::plan_one_initial_with_terrain_recovery`; keep every previously admitted result unchanged. Choose at most one as-yet-untried style from Houses' ordinary compatible seeded order (`style_index.rs::candidate_styles_for_programme`), preferring a matching hinted recipe. Never let the caller supply compatibility, hard floors or a source pin. Unknown/version-mismatched/empty hints mean no recovery. Track attempted styles across existing passes to prevent redraws.

Reconstruct that source with the actual config wealth, variant and seed using existing target-aware resolution (`initial_ground_programme_dimensions`, `automatic_initial_programme_area`, `engine::resolve_urban_architecture_with_budget`); retain existing source/aspect/minimum rules. Reuse existing bounded budget/admission helpers, with explicit counters and at most one recovery source, rather than adding another complete four-source pass. Any poses must be anchored to the reconstructed native entrance/contact, never copied unchanged from smaller witness bounds. Ordinary terrain/roof/access checks remain authoritative; report actual target status and unknown household capacity.

This is preferable to hard-filtering the primary shortlist, which can discard successful sources and still draw a non-fitting variant. It is also narrower than activating `native_single_fit.rs`: that module is currently non-production and covers only plain one-storey Single rectangles, excluding the Roman three-storey/strip and many 01 cases. Its current tests are not evidence for these urban operators.

# Receiver froid intégré — consommateurs UI encore historiques

Le vrai receiver `web/src/ui/urbanScene.ts` expose désormais **`client.runCold(input, options): Promise<UrbanColdSceneResponse>`**, à côté du `run` historique, conservé pour ses consommateurs. La nouvelle branche ne construit jamais `createUrbanSceneAccumulator` ni un préfixe natif croissant.

`UrbanColdSceneInput` exige une source retenue locale et un mode `compact|detailed`, avec seed/keys/settings/overrides. Le transport est construit par allowlist explicite, y compris source/runtime : des propriétés runtime supplémentaires `raster/layouts/partitions/scene/parent` ne traversent pas cette frontière. Options : backend froid, SHA source, sceneId/expectedActive facultatifs, `retainSites` (true par défaut), progress et callback `onProjection(projection, progress)`.

Le résultat est explicitement `{kind:'cold-native-scene', store:{format,sceneId,fingerprint,sourceFingerprint}, counts, siteData, timing?}`. **Aucun `PlacementBatch` fictif, champ `scene`, tableau de contraintes `requests` ou cast de projection native.** `siteData` contient soit les seules projections originales ordonnées + query native vérifiée, soit `{kind:'not-retained',count}` ; cette seconde option ne prétend pas conserver l’accès aux sites d’édition. La query reste runtime-only et n’entre pas dans le manifest portable.

## Garanties du receiver

- Pour chaque chunk : sites projetés ordonnés/offsets vérifiés → `await stage.append(delta, progress)` → callback de cartographie légère → ACK. Le callback n’a ni delta natif ni accumulateur en argument. L’erreur de quota, du callback ou du worker interdit l’ACK et nettoie le staging.
- Le pointeur actif n’est remplacé qu’après vérification de la completion (versions/counts), continuité du flux et identité complète de la query (source révisionnée/seed/keys/culture), puis commit atomique/CAS. La génération précédente reste conservée.
- Invalidation/remplacement/dispose coupe les callbacks et attend le drainage de l’écriture déjà commencée avant nettoyage ; les dispatch suivants attendent cette barrière. Une rafale ne lance donc que le dernier remplacement après drainage, sans collection de chunks abandonnés. Un callback de projection bloqué est relâché par supersession. Les messages concurrents avant ACK/finalisation sont rejetés.
- Extension rétrocompatible : `stage.commit({completion,signal})` et `backend.commit(manifest, expectedActive, {signal})`. L’adapter IndexedDB annule la transaction active, rejette un signal déjà annulé avant transaction, et retire les listeners sur abort/complete/CAS failure. **Après commit durable, une annulation ne peut pas défaire les données : le receiver supprime seulement toute publication UI périmée.** Ce cas est testé ; aucune fausse promesse de rollback tardif.
- `runCold` rejette l’ancien message contenant une scène collectée ou des contraintes originales. Aucun fallback main-thread vers la collecte legacy n’est utilisé pour cette entrée. Le `run` historique conserve son fallback et ses règles existantes.

**Garde de capability amont fermée :** `runCold` force `requireProjectedSiteStream:true`. Le protocole et le worker valident source locale, mode plan explicite et transport progressif avant toute création de moteur/voie legacy. Le bridge reçoit `requireSiteRead:true` et vérifie **les deux** capacités `urban.building-site-pages` et `urban.building-site-read` avant `buildingSitesBegin`. Sur serveur ancien/incomplet, seule la lecture `/status` a lieu : erreur explicite, zéro Begin/page/full-site-read/appel Houses. Le worker vérifie également qu’un descriptor `siteQuery` existe avant de continuer. Les requêtes historiques non flaggées conservent leur compatibilité antérieure.

Produit : `urbanScene.ts`, `urbanSceneProtocol.ts`, `urbanSceneWorker.ts`, `urbanBuildingChunkStore.ts`, `urbanBuildingChunkIndexedDb.ts`, `rust/bridge/urbanBuildingPages.ts`. Tests : nouveaux `urbanSceneColdStreaming.test.ts` (11) et `urbanBuildingChunkIndexedDb.test.ts` (6), `urbanBuildingPages.test.ts` étendu (5), helper mémoire et petite fixture `urban-cold-sites-c.json`. Neuf contraintes originales ont été comparées aux fichiers C figés `001/002/004-request.json` par identité/valeurs et SHA ; les six bâtiments/trois refus proviennent de la fixture C existante. Les offsets sont ceux du petit échantillon, pas un replay de ville complète.

**Receiver/signal : 33 tests verts / 5 fichiers.** Root a confirmé **85 tests verts / 12 fichiers et `tsc --noEmit` vert** sur cette version, log Vitest dans [`web/out/cold-pipeline-integration-20261023/`](../web/out/cold-pipeline-integration-20261023/) (sortie tsc vide, fichier absent). Après fermeture de la garde amont : **33 tests verts / 6 fichiers**, couvrant pages/cold/legacy/source/progress/store ; root reprend le typecheck final. Les tests worker vérifient sept messages flaggés malformés et trois statuses incomplets avec zéro moteur/full-site/Houses/Begin, puis un flux flaggé capable de 65 sites avec ACK. Couverture receiver : ordre persist/preview/ACK, aucun accumulateur, allowlist, source étrangère, quota/callback, stale/latest-only, commit actif annulé ou déjà durable, finalisation précoce/overlap, crash/dispose, metadata vide, listeners/CAS. L’adapter réel est exercé sur un double de transaction : **ni navigateur IndexedDB, quota réel, durabilité après crash, heap/FPS, natif, serveur ou Cargo validé**.
